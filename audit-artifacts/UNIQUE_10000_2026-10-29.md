# 10,000-case audit — results, not a clinical validation claim

**Bottom line: the tested version is not ready for patient deployment.** The
large audit found an actual negation/safety bug that the earlier unit/browser
tests did not expose. Application/model/threshold code was deliberately left
unchanged throughout testing; findings have not been silently fixed or dropped.

Target application: **`aa7d422`**. Real loopback HTTP, authentication, migrated
PostgreSQL schema `audit_unique_cf741a3bc9a4`, live V3, mapping, complete question
loops, and history reads for persisted results. Existing development data was
not used for the generated assessments. No browser automation in this audit.

| Check | Observed |

This **70.45% is a synthetic software-check pass rate, not diagnostic accuracy**.
The cases have declared extraction/routing expectations, not invented disease
labels. Some broad expressions such as “voice changes” are linguistically
ambiguous: conservative non-recognition is a coverage failure under this corpus,
not automatically a dangerous medical error. The infant-fever failures are a
separate, concrete safety-routing defect.

### What was actually varied

- 4,000 routine cases; 1,000 each warning signs, denial, another person's symptoms,
  unsupported symptoms and mixed language; 500 each contradiction and severity.
- 2,833 Swahili-output cases and 7,167 English-output cases, including mixed inputs.
- 5,206 distinct declared symptom/state combinations; 5,945 when the other-person
  target is included; 7,669 category/state/target combinations. **Do not call this
  10,000 different diseases or 10,000 different clinical presentations.** The
  remaining variation intentionally tests wording, context, age, duration and
  answer patterns. No duplicate descriptions or meaningless ID suffixes were used.
- 37,695 expected-state assertions on the 9,000 non-warning-bypass mappings;
  4,194 mismatches (88.87% assertion agreement, not a clinical sensitivity metric).
- Follow-ups: mean **3.03**, maximum **10**; all within the hard ceiling of 20.
- Six workers; **2,502.60 seconds (41.7 minutes)**. Per-case median 1.42s,
  p95 2.78s under this small local concurrent workload, not a deployment benchmark.

### Most important failure: intrinsic negation leaks to neighbouring symptoms

Minimal independently reproduced pair:

```text
I have loss of smell, fever and cough.
  -> loss_of_smell present; fever present; cough present

I have no sense of smell, fever and cough.
  -> loss_of_smell present; fever ABSENT; cough ABSENT
```

“No sense of smell” is a positive loss-of-smell observation. Its “no” incorrectly
negates later, positively reported symptoms. **711 cases** had false-absence
extraction; all contained this expression. **62 still received a named/family
result from the corrupted evidence.** This does not establish whether that name
was medically right, but establishes that the inputs to selection were wrong.

Ten age-zero fever cases then missed the immediate infant-fever route: five
received professional-review guidance and five self-care/review guidance,
instead of the configured immediate assessment pathway. Case IDs:
`3677, 4062, 5596, 7032, 7400, 8332, 8518, 9028, 9333, 9976`.

Example: `I have no sense of smell, a headache, high temperature, eyes itching,
a blocked nose for 2 days.` Age 0, case 4062: fever became absent, two routine
questions followed, and the result was self-care/review. This is a **priority
fix before any patient use**, not something improved by a more permissive gate.

## 2. Unfamiliar-input set: 1,000 additional cases

**1,000 distinct new descriptions; zero forced disease names, exceptions or
declared-check failures.** Five groups of 200: novel metaphors, unsupported
symptoms, unusual code-switching, invented words and pressure to name a disease.
All returned uncertainty/insufficient evidence. Ordinary known symptoms mixed
into those descriptions passed 1,660 mapping expectations.

All 1,000 had unmatched wording: this shows safe withholding, **not semantic
understanding** or correct triage for unknown conditions. Some cases still asked
up to eight questions. See [the separate report](UNFAMILIAR_INPUT_AUDIT_2026-10-29.md).

## 3. Model check with strict effective-input uniqueness

To avoid counting different source IDs or literal ages as different model tests,
the strict check keys on **present features + absent features + the demographic
group actually used by V3**. Its current model uses age groups, not sex or every
individual age. **732 duplicate effective inputs and one empty profile were
skipped**, not counted, until exactly **10,000 different effective inputs from
10,000 different full source profiles** were obtained. Selection was label-blind.

This is a diversity-selected reporting sample from the existing DDXPlus test
fold, excluding training/validation signatures. It is **not** new independent
validation, representative Kenyan data, an API triage test, or threshold tuning.

| Strict unique-input source metric | Result |
|---|---:|
| Cases / distinct effective model inputs / distinct source profiles | **10,000 / 10,000 / 10,000** |
| Underlying top-ranked class correct before withholding | **7,360 (73.60%)** |
| Specific names permitted | **2,617 (26.17% coverage)** |
| Correct specific names | **2,491 / 2,617 (95.19%)** |
| Wrong specific names | **126** |
| Correct specific names across all cases | **24.91%** |
| Family-only answers | **453** |
| Family answers whose source class belonged to the declared family | **441 / 453 (97.35%)** |
| Uncertain/withheld | **6,930** |

Most named errors were acute vs chronic rhinosinusitis (**64**) and flu vs URTI
(**32** across both directions). Five source-pneumonia records received mild
specific names (two URTI, two influenza, one bronchitis). Five more appeared among
family-only answers; the other seven family disagreements were bronchitis.
These observations justify review; family-class membership is not proof of a
viral cause, and this source-only check did not exercise API warning triage.

The first, separately retained 10,000-full-profile sample had **9,958 literal
partial model inputs**, 24.12% specific-name coverage and 95.61% selective accuracy.
It is preserved for transparency, but the stricter numbers above are the relevant
answer to “do not count the same model input again”. **Do not sum these two
samples as independent validation or 20,000 new unique source cases.**
